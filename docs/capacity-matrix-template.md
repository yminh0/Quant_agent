# Capacity Matrix 입력 템플릿

## 1. 목적

이 문서는 팀원이 자신의 정보를 한 줄로 입력하면, 리더가 팀의 가용량·역량·현재 작업량·백업 공백을 확인할 수 있도록 만든 입력용 capacity matrix입니다.

이 표의 `capacity`는 **기준 기간에 해당 프로젝트에 실제로 투입 가능한 시간**을 뜻합니다. 총 근무시간을 그대로 적지 말고, 회의·정기 운영·장애 대응·다른 프로젝트·휴가 등 이미 예정된 시간을 제외합니다.

## 2. 리더가 먼저 고정할 값

| 항목 | 설정값 |
|---|---|
| 기준 기간 | `[YYYY-MM-DD ~ YYYY-MM-DD]` |
| 시간 단위 | `시간/주` 또는 팀이 합의한 단위 하나 |
| 입력 마감일 | `[YYYY-MM-DD]` |
| Confidence 허용값 | `H`, `M`, `L` |
| 역량 태그 목록 | 팀이 합의한 표준 태그를 별도 목록으로 관리 |
| 검토 주기 | 기준 기간이 바뀔 때마다 또는 팀이 합의한 주기 |

> 기준 기간과 시간 단위는 모든 행에서 동일해야 합니다. 기간이 다르면 같은 표에서 합산하지 않습니다.
 
## 3. 팀원 입력용 표

아래 표에서 팀원은 **자기 행의 값만 입력**합니다. `[입력]` 표시는 지우고 실제 값을 넣습니다.

| 실명 | 가용 시간 (시간/주) | 역량 (표준 태그) | Confidence (H/M/L) | WIP (진행 중 건수) | Backup (대체 담당자 실명) |
|---|---:|---|---|---:|---|
| [입력] | [입력] | [입력] | [입력] | [입력] | [입력 또는 없음] |
| [입력] | [입력] | [입력] | [입력] | [입력] | [입력 또는 없음] |
| [입력] | [입력] | [입력] | [입력] | [입력] | [입력 또는 없음] |
| [입력] | [입력] | [입력] | [입력] | [입력] | [입력 또는 없음] |
| [입력] | [입력] | [입력] | [입력] | [입력] | [입력 또는 없음] |

### 복사 가능한 헤더

```text
실명	가용 시간 (시간/주)	역량 (표준 태그)	Confidence (H/M/L)	WIP (진행 중 건수)	Backup (대체 담당자 실명)
```

## 4. 입력 규칙

| 필드 | 팀원이 입력할 값 | 입력 규칙 | 잘못된 예 |
|---|---|---|---|
| 실명 | 사내 roster와 동일한 실명 | 별칭·이니셜을 쓰지 않고 한 사람당 한 행 | `MJ`, `데이터팀` |
| 가용 시간 | 숫자 | 기준 기간에 프로젝트에 실제 투입 가능한 시간만 입력. 단위는 표의 설정값을 따름 | `40시간 정도`, `많음` |
| 역량 | 표준 태그 1개 이상 | 자유 문장 대신 팀이 합의한 태그를 쉼표로 구분 | `데이터를 잘함` |
| Confidence | `H`, `M`, `L` 중 하나 | **역량 수준이 아니라 이 입력값의 확실성**을 표시 | `상`, `높음`, `90%` |
| WIP | 0 이상의 정수 | 현재 시작했지만 아직 끝나지 않은 작업의 개수. 완료·대기·백로그는 제외 | `많음`, `3~5` |
| Backup | roster에 있는 다른 사람의 실명 또는 `없음` | 해당 역량·업무를 실제로 이어받을 사람. 이름만 올리고 인수인계가 안 된 경우에는 `없음`으로 처리 | `누군가`, `팀장 확인` |

### Confidence 기준

| 값 | 의미 | 후속 조치 |
|---|---|---|
| `H` | 캘린더·현재 작업·부재 일정을 확인했으며 기준 기간의 값이 안정적임 | 일반 검토 |
| `M` | 일부 변동 가능성이 있거나 다른 업무와의 충돌을 아직 모두 확인하지 못함 | 리더가 기준 기간 시작 전에 확인 |
| `L` | 가용시간·WIP·역량 중 하나 이상이 불명확하거나 급격한 변동이 예상됨 | capacity 합산 전에 확인 필요 |

## 5. 관리자가 읽는 방법

1. **가용량 합산**: 사람별 `가용 시간`을 역량 태그별로 묶어 합산합니다.
2. **수요와 비교**: 작업별 예상 소요시간 또는 우선순위가 이 표에 없으므로, 이 표만으로 일정 확정이나 과부하 판정을 하지 않습니다.
3. **WIP 확인**: WIP는 현재 진행 중인 작업 수입니다. 작업 크기가 서로 다르면 건수만 비교하지 말고 WIP 상세를 추가로 확인합니다.
4. **Confidence 확인**: `L` 행은 숫자를 그대로 확정값으로 사용하지 않고, 해당 팀원과 기준 기간·고정업무·WIP를 다시 맞춥니다.
5. **Backup 공백 확인**: `없음`이거나 본 담당자 외에 같은 역량을 맡을 사람이 없으면 운영 리스크로 표시합니다.
6. **행동으로 연결**: 백업이 필요한 행에는 문서화, shadowing, 인수인계 또는 책임자 교대 계획을 별도로 등록합니다.

## 6. 스프레드시트 데이터 검증 설정

팀원이 입력만 하도록 다음 검증을 설정합니다.

| 열 | 검증 방식 |
|---|---|
| 실명 | 팀 roster 목록에서 선택 |
| 가용 시간 | 숫자이며 음수가 아님 |
| 역량 | 팀이 관리하는 표준 태그 목록에서 선택. 여러 개면 쉼표로 구분 |
| Confidence | 드롭다운: `H`, `M`, `L` |
| WIP | 0 이상의 정수 |
| Backup | 팀 roster 목록 또는 `없음` |

조건부 서식은 `Confidence=L`과 `Backup=없음`에만 적용하고, WIP 과다 기준은 팀이 정한 운영 기준을 별도로 입력한 뒤 사용합니다. 임의의 고정 숫자를 표준으로 넣지 않습니다.

## 7. 선택 입력: WIP 상세

WIP 건수만으로 작업량 차이를 설명하기 어려운 팀은 입력 표 뒤에 다음 보조 표를 추가합니다. 기본 표의 필수 입력을 늘리지 않고, 리더가 필요한 행만 요청하는 방식입니다.

| 실명 | WIP 작업명 | 상태 | 남은 예상시간 | 막힘/의존성 |
|---|---|---|---:|---|
| [입력] | [입력] | [진행/대기/차단] | [입력] | [입력 또는 없음] |

## 8. 조사 결과와 설계 근거

| 확인한 원칙 | 템플릿에 반영한 내용 | 출처 |
|---|---|---|
| 팀 capacity는 정식 업무뿐 아니라 회의·운영·예상 밖의 업무까지 포함해 시간 단위로 확인해야 함 | `가용 시간`을 총 근무시간이 아닌 실제 투입 가능 시간으로 정의 | Atlassian, [Capacity Planning: a Step-By-Step Guide and Template](https://www.atlassian.com/team-playbook/plays/capacity-planning) |
| capacity planning은 예상 수요에 필요한 자원과 실제 가용 자원을 비교하고, 과소·과다 할당을 피하는 활동임 | 기준 기간·단위 고정, 가용량 합산과 수요 비교를 분리 | Microsoft Azure Well-Architected, [Architecture strategies for capacity planning](https://learn.microsoft.com/en-us/azure/well-architected/performance-efficiency/capacity-planning) |
| WIP는 특정 시점에 진행 중인 작업 수이며, 흐름을 개선하려면 WIP를 제한하고 작업량을 관찰해야 함 | WIP를 진행 중 건수로 별도 기록하고, 건수만으로 작업 크기를 판단하지 않도록 안내 | Kanban University, [The Official Guide to The Kanban Method](https://kanban.university/kanban-guide/) |
| primary/secondary 담당 구조에서 secondary는 primary의 backup·fall-through·에스컬레이션 역할을 할 수 있으며 역할은 팀마다 다름 | Backup을 이름으로 명시하고, `없음`을 공백이 아닌 위험 신호로 관리 | Google SRE, [Being On-Call](https://sre.google/sre-book/being-on-call/), [Dealing with Interrupts](https://sre.google/sre-book/dealing-with-interrupts/) |

`Confidence`의 H/M/L은 위 자료에서 공통으로 정해진 산업 표준값이 아니라, 이 matrix의 입력 품질을 운영하기 위한 **팀 로컬 규칙**입니다. 역량 수준과 입력값의 확실성을 혼동하지 않도록 별도 의미로 정의했습니다.

## 9. 최소 운영 절차

1. 리더가 기준 기간·단위·표준 역량 태그를 고정합니다.
2. 각 팀원이 자기 행을 입력합니다.
3. 리더가 빈 값, 잘못된 값, 중복 실명, `Confidence=L`, `Backup=없음`을 확인합니다.
4. 역량별 가용시간을 합산하고, 실제 작업 수요와 비교합니다.
5. 합의한 기준 기간이 끝나면 가용시간·WIP·backup 변동을 갱신합니다.

### 적용하지 않은 것

- 모든 팀에 동일한 WIP 상한을 강제하지 않았습니다. 작업 크기와 운영 방식이 다르므로 팀 기준이 필요합니다.
- 가용시간의 일정 비율을 임의로 buffer로 차감하지 않았습니다. 회의·운영·부재 등 실제 고정 업무를 먼저 반영해야 합니다.
- Confidence를 역량 숙련도 점수로 사용하지 않았습니다. 숙련도 평가가 필요하면 별도 필드를 추가해야 합니다.
