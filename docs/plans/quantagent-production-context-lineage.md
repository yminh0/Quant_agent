## 범위 충돌 해결

| 충돌 | 결정 | 이유 |
|---|---|---|
| 온디맨드를 고치기 vs. 온디맨드를 제거하기 | 제거·명시적 비활성화를 먼저 한다. 과거 결과만 읽기 전용으로 남긴다. | 현재의 오류·mock 위험을 새 요청 흐름에 노출하지 않기 위해서다. |
| 낮은 성과를 올리기 vs. 성과의 신뢰성을 높이기 | 신뢰성·표시 정확성을 먼저 한다. 성과 목표는 비목표다. | 편향·기본값 제거는 수치를 낮출 수 있으며, 이를 실패로 취급하면 다시 오도한다. |
| 인증 후 UX를 바로 PASS | 유효한 세션 증적이 들어올 때까지 `미검증`으로 둔다. | 세션을 우회하거나 계정을 사용하지 않는다는 금지선을 지킨다. |
| 기존 문서의 문제를 확정 사실로 사용 | current HEAD 상태를 재검증한다. | 코드가 변경됐을 수 있어 과거 문서가 현재 동작을 증명하지 않는다. |
