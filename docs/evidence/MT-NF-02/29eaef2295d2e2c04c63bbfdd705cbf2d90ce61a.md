`tests/contracts/test_metric_api_serialization_contract.py:84`는 공개 metric마다
직렬화 필드를 registry 설명과 1:1로 대조하고, availability를 이렇게 못 박는다.

```python
if detail["is_available"]:
    assert detail["value"] is not None
    assert detail["unavailable_reason"] is None
else:
    assert detail["value"] is None
    assert detail["unavailable_reason"]
```

즉 값이 없으면 `value`가 **`0.0`이 아니라 `None`** 이고, 그때는 사유 문자열이
반드시 존재한다. 두 방향 모두 단언되므로 "reason 없는 unavailable"과
"unavailable인데 숫자가 남아 있는" 경우가 함께 막힌다.

생산 측 구현은 `ai/ai_graph/nodes/backtest.py:3948`
`_undefined_metric_availability`이며, 엔진 경고를 읽어
`{"value": None, "unavailable_reason": reason}`를 세운다. native 경로의 `reason`과
QuantStats 경로의 `warning`을 둘 다 받도록 되어 있다(3954-3957행 주석 참조).
walk-forward 표본이 부족하면 `out_sample_return`도 같은 형태로 마스킹된다
(1639-1651행).
