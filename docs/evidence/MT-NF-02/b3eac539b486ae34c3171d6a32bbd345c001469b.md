## 구현 직접 검토

관련 구현: `ai/ai_graph/nodes/backtest.py`, `ai/ai_graph/quant_performance.py`, `ai/ai_graph/quant_explanations.py`, `ai/ai_graph/schemas.py`

핵심 함수 `_is_numeric_metric`(`ai/ai_graph/nodes/backtest.py`):
```python
def _is_numeric_metric(value: Any) -> bool:
    if isinstance(value, bool) or value in (None, ""):
        return False
    try:
        parsed = float(value)
    except (TypeError, ValueError):
        return False
    return math.isfinite(parsed)
```

이 값을 실제 직렬화에 쓰는 `_metric_detail`(`ai/ai_graph/quant_performance.py`):
```python
is_available = _is_numeric_metric(value)
value=round(float(value), METRIC_ROUND_DIGITS) if is_available else None,
is_available=is_available,
unavailable_reason=None if is_available else (unavailable_reason or explanation.get("unavailable_reason")),
```

| # | 항목 | 판정 | 근거 |
|---|---|---|---|
| 1 | unavailable metric을 `0.0`으로 zero-fill하지 않음 | **PASS** | `value=... if is_available else None` — unavailable이면 항상 `None`, `0.0` 대체 없음. |
| 2 | 실제 값 `0`과 unavailable/null을 구분 | **PASS** | `_is_numeric_metric(0.0)`은 `math.isfinite(0.0) == True`이고 `0.0 not in (None, "")`이므로 `True`를 반환 — 진짜 0은 `is_available=True, value=0.0`로 보존되고 `None`/`""`/non-finite와 명확히 분리된다. |
| 3 | NaN/+inf/-inf 등 non-finite 값 안전 처리 | **PASS** | `math.isfinite(parsed)`가 NaN/+inf/-inf를 명시적으로 배제 → 그런 값은 `is_available=False, value=None`이 되어 `round()`에 도달조차 하지 않는다. |
| 4 | `is_available` 상태 전달 | **PASS** | `is_available` 필드가 `PublicMetricDetail`에 항상 포함되어 직렬화된다(테스트의 `METRIC_DETAIL_FIELDS`에도 명시). |
| 5 | unavailable reason 보존 | **PASS** | unavailable일 때 명시적 `unavailable_reason`을 우선 사용하고, 없으면 registry/explanation의 기본 reason으로 폴백한다. 대응 contract test에서 unavailable metric의 reason 전달 계약이 충족됨을 함께 확인했다. |

5개 전부 PASS. 대상 테스트가 이 `is_available`/`value`/`unavailable_reason` 삼중 불변식을 정확히 이 코드 그대로 단언하고 있음을 직접 확인했다.
