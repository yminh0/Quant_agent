## Finding: the deployed API surface contradicts the retirement

`GET /api-status` on the deployed service returns, verbatim:

```json
{"method":"POST","path":"/analysis-jobs","state":"local_sync",
 "summary":"Create and run an analysis job through the local graph."}
```

while the same response marks the two other retired routes correctly:

```json
{"method":"GET","path":"/api/reports/{report_id}","state":"retired", …}
{"method":"POST","path":"/ai/daily-digest","state":"retired", …}
```

`_endpoint_statuses()` is a **static list**. The `POST /analysis-jobs` entry hardcodes
`state="local_sync"` and was never updated when the route was retired, and it does not
read `app.state.legacy_analysis_jobs_enabled`. Two consequences:

1. The public API surface summary states that a retired route creates and runs analysis
   jobs. That is the exact failure mode the row's risk column names — "기존 consumer가
   원인을 못 알 위험" — reintroduced through the inventory endpoint rather than through
   the route itself.
2. `api-status` cannot be used as evidence about this row either way. Because the field
   is static, its value tells us nothing about whether `APP_ENV` is set to `production`
   on the deployed service, and therefore nothing about whether the 410 is live there.

This bundle does not change code. The fix belongs to `OD-API-01`'s implementation lane:
either derive the state from `app.state.legacy_analysis_jobs_enabled`, or hardcode
`retired` to match the other two retired entries.

## Not covered

- **Whether the 410 is actually in force on the deployed service.** The route's
  `require_preflight_user` dependency resolves before the handler body, so an
  unauthenticated probe returns `401` and cannot distinguish a retired route from a live
  one. Settling this needs either an authenticated session or the server's `APP_ENV`
  value; neither was available here, and no POST was sent to the deployed service.
- Server-side job, background-task, and audit counts. The suite proves zero side effects
  in-process. A claim about the deployed store requires reading it on the server.
