### 공개 API 경계 (outermost)

`TestClient`로 두 endpoint를 직접 호출해 response shape을 실측했다 (아래 7번 재현 절차의 probe 코드 블록
참조). 실측 결과:

| Endpoint | status_code | 응답 최상위 key | `public_create_retired`의 정확한 JSON path | `retryable` 존재 여부 |
|---|---|---|---|---|
| `POST /analysis-jobs` | `410` | `["detail"]` | `detail.code` | 없음 (최상위·`detail` 내부 모두 부재) |
| `POST /api/research/jobs` | `410` | `["detail"]` | `detail.code` | 없음 (최상위·`detail` 내부 모두 부재) |

두 endpoint 모두 **job 생성 이전에** HTTP `410`을 반환하며, 응답 body는 FastAPI의 `HTTPException(detail=...)`
기본 직렬화 방식대로 `{"detail": {...}}` 형태로 감싸진다 — 최상위 key는 `detail` 하나뿐이고, 실제 `code`
필드는 `detail.code`에 있다(최상위 `code`가 아니다). `retryable` 필드는 이 응답의 어느 위치에도 존재하지
않는다 — `retryable=false`가 이 응답에서 측정된 값이라고 기록하지 않는다.

구현 위치: `ai/ai_graph/execution_boundary.py`의 `retired_public_create_detail()`이 이 dict를 만들고,
`ai/ai_graph/api.py`의 두 job 생성 엔드포인트에서 `_production_runtime()`이 참일 때
`HTTPException(status_code=410, detail=retired_public_create_detail(...))`로 이 경계를 먼저 평가한다.
