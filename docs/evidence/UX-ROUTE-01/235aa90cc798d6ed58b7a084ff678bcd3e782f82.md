## 7. 재현 절차

검증 환경은 Windows다. 아래 명령 블록은 모두 **Git Bash 기준**이다(이번 검증에서 실제로 실행한 셸과 동일). PowerShell에서 재현하려면 `curl` 대신 `curl.exe`를, SHA-256 계산에는 `Get-FileHash -Algorithm SHA256`을 사용해야 하며, 한 블록 안에서 두 셸 문법을 섞지 않는다 — 이 evidence의 명령은 PowerShell로 별도 재변환·재실행하지 않았다.

1. disposable worktree에서 tested SHA를 detached checkout하고 그 worktree로 이동한다(Git Bash):

   ```bash
   git worktree add --detach <disposable-path> 235aa90cc798d6ed58b7a084ff678bcd3e782f82
   cd <disposable-path>
   ```

2. checkout이 정확한 tested SHA인지 확인한다(Git Bash) — 출력이 아래 40자 SHA와 정확히 일치해야 한다:

   ```bash
   git rev-parse HEAD
   # 기대값: 235aa90cc798d6ed58b7a084ff678bcd3e782f82
   ```

3. `npm test`에 필요한 의존성을 설치한다. 이 저장소는 `fe/package-lock.json`을 커밋하고 있고, `.github/workflows/code-check.yml`·`.github/workflows/deploy.yml`이 실제로 `npm ci`를 사용하므로 동일한 명령을 쓴다(임의로 지어낸 설치 명령이 아님, Git Bash):

   ```bash
   cd fe
   npm ci
   ```

4. WBS 지정 명령을 실행하고 exit code와 `tests`/`pass`/`fail` 수를 기록한다(Git Bash, `fe/` 디렉터리에서):

   ```bash
   npm test
   ```

5. `fe/`에서 repository root로 돌아온 뒤 production endpoint를 GET으로 요청한다(Git Bash):

   ```bash
   cd ..
   curl -s -D - -o <os-temp-dir>/body.html -w "%{http_code} %{redirect_url} %{url_effective} %{size_download} %{content_type}" https://qt-agent.kro.kr<path>
   ```
   (`<path>`는 `/`, `/ai-api/health`, `/login`, 임의 미존재 경로, `/dev/email-template`, `/@vite/client`, `/src/main.tsx`)

6. `/`의 응답 HTML에서 `<script src=...>`, `<link rel="stylesheet" href=...>` asset URL을 추출한다.

7. 추출한 JS/CSS asset을 다운로드하고 SHA-256 hash를 기록한다(Git Bash):

   ```bash
   sha256sum <downloaded-file>
   ```

8. 다운로드한 HTML/JS/CSS 전체에서 `email-template`, `EmailTemplatePreview`, `emailTemplatePreview`, `@vite/client`, `@react-refresh`, `sourceMappingURL`, `localhost`, `/src/main.tsx` 문자열을 검색하고 건수를 기록한다.

임시 파일은 OS 임시 디렉터리(`<os-temp-dir>`)를 사용하며, 개인 로컬 절대경로는 이 evidence에 기록하지 않는다.
