## Why the row could not have been satisfied at the parent commit

Documenting an exit-code contract is only meaningful if the command honours it. At
`origin/main` it did not: on this platform the CLI guard never matched, so **every**
invocation exited 0 with no output — including malformed boards. Writing "malformed board
→ exit 1" then would have documented an aspiration, not the program.

`c8fb626` repaired the guard first; this row's document then records measured behaviour.
That ordering is why `PM-GOAL-00` and `PM-GOAL-01` share a runner here.

On pristine `origin/main` (`470d33e`) the same command reported `pass 1 · fail 4`:

- `the command reports a malformed board as non-passing` — `AssertionError: 0 !== 1`,

- the other three — the fixture pinned `c3a5bc46`, a commit from the pre-migration
  history, and `assertReachableCommit` requires evidence SHAs to be ancestors of `HEAD`.
  On an orphan root that commit is unreachable. Fixed in `72da240` by resolving the
  fixture SHA with `git rev-parse HEAD` instead of pinning one.

Exit-0 and non-zero examples for the document were produced in one run against
temp-directory boards whose snapshot SHA is this checkout's `HEAD`; they are tabulated in
[`PM-GOAL-00`'s bundle](../PM-GOAL-00/72da24067c54067989f58d0947271281c41d46c1.md).
