## Done 조건별 독립 검토

- **redaction PASS**: 실제 production 함수(URL/시크릿 redaction 로직)를 직접 호출하는 테스트와, 실제 FastAPI 요청 처리 경로(미들웨어 포함)를 통해 검증하는 테스트 양쪽에서 확인. 후자는 `synthetic secret-like test values`(AWS 액세스 키 스타일, GitHub 토큰 스타일, OpenAI API 키 스타일 패턴 등 테스트 전용 가짜 문자열)를 request-id 헤더로 주입해도 응답 헤더와 로그 어디에도 원문이 남지 않음을 실제 코드 경로로 확인했다 — mock/fixture assertion에 그치지 않고 production code path를 경유한다.
- **trace correlation 유지**: 정상 발급된 trace id는 응답 헤더와 로그 라인에 일관되게 유지됨을 확인. redaction이 발생하는 경로에서도 교체된 새 id가 헤더·로그 간에 일관되게 correlate되어, redaction이 correlation 자체를 손상시키지 않음을 확인했다.
- **선택된 테스트 중 일부의 대표성 한계**: `-k 'redaction or correlation'`로 선택된 7개 중 1개는 AI 백테스트 저장소의 correlation ID 전파를 fixture/fake 객체 기반으로 검증하는 **사전 존재 테스트**이며, 이번 implementation commit이 변경한 파일에 포함되지 않는다. 이름이 필터에 우연히 매치되어 선택된 것으로, 이 WBS 구현을 대표하는 핵심 근거로 취급하지 않았다.
- **"trace correlation 100%"의 해석 범위**: 이번 QA는 실제 구현과 지정 literal verifier가 다루는 범위 — `RuntimePerformanceMiddleware`가 적용되는 telemetry 대상 경로(옵트인 설정이 켜져 있을 때의 지정된 GET 경로들) — 안에서 100% correlation을 검증한 것이다. 이 결과를 애플리케이션 전체 endpoint에 대한 correlation 보장으로 확대 해석하지 않았다.
- **R/O/C 관련 상태**: 이번 QA는 R/O/C(운영 배포·관측·규정 증적)가 완료됐다고 주장하지 않는다. literal verifier 재현과 이 row의 Done 조건에 대한 로컬 QA verdict는 R/O/C와 별개이며, R/O/C는 이 verdict와 무관하게 계속 pending 상태로 남는다.
